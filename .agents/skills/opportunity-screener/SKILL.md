# 台股與台灣 ETF 機會篩選

先讀 `docs/PROJECT.md` 與 `docs/research-data-contract.md`。方法改寫自 InvestSkill stock-screener / etf-analysis、AI Berkshire quality-screen / industry-funnel；完整版本與授權見 `docs/skill-provenance.md`。這是研究優先度篩選，不是交易系統。

## 輸入與範圍

接受代碼清單、產業、主題或指數。記錄截止日期、投資期間、基準、流動性下限、排除條件及權重。未指定時：最近已公開資料、中長期觀察、股票以交易所產業分類分組，ETF 按底層資產／策略分組。不擅自設定個人可承受虧損或倉位。

先取官方商品主檔核對 TWSE/TPEx、個股／ETF、幣別及交易狀態。全市場／指數模式須有截止日完整母體與成分股；無法取得時標為「樣本篩選」，報告母體、納入數及缺漏數，不聲稱全市場最佳。台灣掛牌海外股票、債券、主動式、槓桿與反向 ETF 分類處理。

## 步驟一：資料品質與交易風險閘門

1. 取得最近交易日價格、20 日成交金額／成交量、交易狀態、公司行動；取近 5 年與最近四季財報、近 12–24 個月營收。10 年不足時用可得期間，不假裝滿足長期檢驗。
2. 注意／處置、變更交易方法、停止交易、下市風險、重大訊息、會計師保留意見等各列旗標；區分官方事實與研究判斷。無法交易者不進可執行候選榜，仍列排除原因。
3. 使用者未給成交金額下限時，只揭露流動性與可比較性，不隨意刪除小型股；大型預期部位須另外評估成交參與率與退出天數。
4. 價格或財報身分不明、重大來源衝突未解決者列「待補資料」，不得靠估計進榜。

## 產業／主題入口的機會發現

借用 InvestSkill industry-map 與 competitor-analysis：先界定主題、上下游邊界與需求來源，列供應商→客戶的有向關係、可信供應者數、替代難度、誰捕捉利潤以及稀缺性可能遷移到哪一層。沒有證據不打瓶頸分數。不能只選新聞熱門或名稱含主題的公司；用產品／收入占比、客戶或官方法說驗證關聯程度，未知就列未知。

對同一產業節點建立可比同業組，列定價權、切換成本、競爭替代、資本密集與主要風險。高成長產業不保證成員股東回報；產業鏈有利位置仍須過財務、估值與流動性檢查。海外競爭者可作脈絡，但不偷偷加入台灣投資母體。少於五家可比資料只輸出質性研究優先理由，不造排名。

## 步驟二：個股品質初篩

沿用 AI Berkshire 的長期品質檢查概念，逐項顯示數值、期間與證據；以下上游門檻只是風險提示，不是適用所有台股的淘汰定律：

| 檢查 | 參考旗標 | 台灣適用調整 |
|---|---|---|
| 長期 ROE | 10 年平均 < 8% | 不足十年揭露窗口；負權益不評分 |
| 累積 FCF | 5 年累計 < 0 | 區分擴產投資與營運失血，保留資本密集產業理由 |
| EBIT／利息支出 | < 2 倍 | 零利息列不適用；金融業不用此指標 |
| 長期毛利率 | < 15% | 電子代工／通路以周轉與 ROIC 解釋，不一律排除 |
| 現金轉換 | 5 年 OCF／NI 偏弱（參考 0.7） | 淨利非正年份不直接平均比率，另列累計現金流與淨利 |
| 長期淨利率 | < 5% | 高周轉薄利與循環產業單列同行及完整週期比較 |
| 股數稀釋 | 5 年增加 > 20% | 排除拆股機械影響；分清股票股利、現增、併購與可轉債 |

不能用「資料不足」判定通過。擴產期、新上市及高周轉模式可人工豁免，但須附證據、代價與重評條件。銀行／保險改看資本適足、逾放及覆蓋、承保／投資品質與主管機關揭露；不足時改做專題研究，不與非金融業直接混排。

## 步驟三：個股五因子排序

保留 InvestSkill 的五維與預設權重：估值 20%、品質 25%、動能 20%、籌碼 15%、成長 20%。以下百分位、覆蓋與分層規則為本專案公開在地化設定，未經績效回測。

| 維度 | 等權子因子（僅限可比口徑） |
|---|---|
| 估值 | TTM PE、PB、EV/EBITDA、FCF yield；前三項低佳，最後高佳；無效分母列 N/A |
| 品質 | ROE、ROIC、OCF／正淨利、負債／資產（低佳）；金融業另組且不用 ROIC／一般槓桿比較 |
| 動能 | 3／6／12 個月相對適當含息基準報酬（高佳）；不足上市期間列 N/A |
| 籌碼 | 20／60 交易日三大法人淨買賣股數／同日股數、最近可得內部人持股變動；分別列來源與限制 |
| 成長 | 最近 3 個月合計營收 YoY、TTM 營收 YoY、正基期 TTM EPS YoY、營業利益率年變動 |

- 同產業可比組至少 5 家，對各子因子做百分位：高佳分數 = `10 × (平均名次−1)/(有效樣本數−1)`，由小到大排名並列取平均名次；低佳用 `10−高佳分數`。每項列有效樣本數；不足五家則不給該項數值分數，只做描述。
- 維度分數為可得子因子平均，至少一半子因子有效才成立。覆蓋率 = 有效子因子數／原定適用子因子數；排除結構性不適用須說明，不能把缺資料說成不適用。
- 只有五維都成立且各維覆蓋率 ≥ 75% 才給正式總分 `Σ(維度分數×權重)`；否則列「資料不足，不排名」。缺失不給零分，也不默默重配權重。
- 依事前分組排名；不同產業百分位分數不可宣稱絕對投資價值相等。法人買超不是獲利保證；融券、借券、集保股權分散各是不同口徑，不冒稱美股 short interest／13F 等價物。
- 不套上游美股固定美元市值、5 美元股價、SPY 基準或分析師修正資料。循環股同列正常化獲利，避免高峰低 PE 誤判。

## 步驟四：ETF 獨立篩選

ETF 不使用公司五因子總分。先核對公開說明書、指數方法／主動策略、總費用、規模、完整持股、NAV、成交價、配息來源與存續條件；與同類 2–3 檔比較。

1. 成本：經理費、保管費、實際總費用分開；同類比較，避免只比名目費率。
2. 追蹤：`TD = 基金 NAV 含息報酬 − 同口徑指數含息報酬`；TE = 同頻超額報酬標準差 × √每年觀察期數。列頻率、窗口、稅務與幣別；不可用價格報酬替代 NAV 追蹤。主動式只評基準相對績效，不冒稱指數追蹤品質。
3. 流動性：20 日平均成交金額、可得買賣價差、規模與底層流動性；`折溢價=(價格/NAV−1)×100%`，不同時間資料只做參考，盤中估計 NAV 與正式 NAV 分開。
4. 曝險：前十大與單一持股、產業、國家、底層幣別、換股規則、台積電／半導體集中；跨境商品另看休市與匯率。
5. 配息：近 12 個月實際配息／截止日價格，註明歷史非預測；收益平準金、已實現資本利得、股利／利息等依實際收益分配公告分拆，不把配息當額外報酬，不把收益平準金逕稱收益或全數本金。
6. 特殊結構：債券加看有效存續期間、信用、到期殖利率與避險；期貨型看轉倉；槓反看每日重設與路徑風險；主動式看經理人及策略漂移。長期核心需求遇槓反／不相符曝險，直接列「用途不符」，不得用高分抵銷。
7. 有持倉才算穿透重疊 `Σ min(ETF 成分權重, 組合成分權重)`；只有前十大時為下界，不算完整重疊。無持倉列未評估，不預設購入 10%。

第一階段以各項「符合／警示／未驗證／用途不符」呈現 ETF 適配度，不移植上游美國 AUM／稅表門檻，也不與個股總分混排；不宣稱重現上游 ETF Fitness Score。

## 輸出與交接

以 Markdown 保存 `docs/reports/YYYY-MM-DD-opportunity-screen.md`，同日重跑加版本尾碼，不覆蓋：

1. 資料與來源摘要、輸入條件、完整母體／樣本與排除統計。
2. 個股榜：代碼｜市場｜產業｜五維分數｜總分／未排名原因｜覆蓋率｜品質旗標｜信心。
3. ETF 表：代碼｜資產／策略｜費用｜TD/TE｜NAV 時間｜折溢價｜流動性｜集中度｜配息來源｜適配狀態｜缺口。
4. 個股前 3 名研究卡：被低估的可能原因、支持證據、最強反證、催化劑與日期、失效條件。排除／低排名者列可重新納入條件，不能只寫「不好」。
5. 產業共振、資料偏誤（存活者／前視／樣本）、重跑條件與來源／計算附錄。

交接 `company-research` 深查；分數僅代表同組研究優先度。新財報、營收、ETF 換股／費用變更或 30 日到期時重跑。不要生成無證據的買賣指令。


## 結構化交換與核准邊界

執行前依 `docs/skill-contracts.md` 正規化輸入；使用對應的 `schemas/opportunity-screener.input.schema.json`。輸出同時提供 Markdown 報告與符合 `schemas/opportunity-screener.output.schema.json` 的 JSON（同名 `.json`）。格式檢查後仍須人工逐項完成契約文件的語義品質檢查；尚無 API adapter／財務計算執行器，不能宣稱已自動執行。

缺關鍵證據時 meta.status=partial 或 blocked、數值 null、列出 data_gaps，不能用合成數字完成報告。所有產物 approval_status=draft。與已核准 thesis 的差異只形成新提案，不修改原版 KPI、估值假設、失效門檻或實際持倉；新增核准版本須使用者明確確認。不得自動下單。

若內容含私人持倉、個人決策或帳戶資訊，改寫至使用者指定的私有儲存，不存入 Git；公開／匿名報告才使用上述 docs 路徑。風險事件保留 event_id，後續跨 Skill 合併時不重複計數。


## Task 2：ChatGPT 交接與輸出

開始前依 `docs/CHATGPT_HANDOFF.md` 讀 manifest、canonical 檔案及全部依賴，核對 revision／完整 Git SHA；不因技能名稱出現在對話就宣稱已讀或執行。自然語言分析可互動完成；資料查詢、Python 排名及驗算只能在能力可用且實際執行時標示完成。

輸出 Candidate List、篩選理由、來源、研究優先度及不確定／缺漏；Research Priority 為 high／medium／low／unranked，說明依據。資訊不可比時給 unranked；它不是獲利概率。各資產類型分開，透明記錄所有調整與排除。

篩選 Markdown 以 `docs/INVESTMENT_MEMO_TEMPLATE.md` 保留適用章節（不足處明示 screening／未深研），原 screener JSON 保留作工作表。若為候選生成結構化提案，唯一提案契約是 `schemas/thesis-proposal.schema.json`：research_stage=screening，status 只能 draft／needs_information；不把分數直接變成完整投資論點或核准門檻。單一候選完成深研後，由 company-research 產出 Memo + Thesis Proposal。


## Task 2.1：研究優先度與現在投資是兩個問題

候選比較增加三道分欄：Asset Quality、Entry Attractiveness、Portfolio Suitability；完整方法與決策判準由 company-research 的 Task 2.1 節維護，不另養一套。產品品質只能支持 Gate 1，不能因知名、低名目費率、過去績效或高配息就推論現在可投資。初篩未取得價格／NAV、底層估值、費後三情境與風險時，Gate 2 標 Insufficient Evidence；未有實際持倉、風險承受與資金需求時，Gate 3 必須 Not Assessed。

在 Candidate List 加研究價值／需解答問題、證據覆蓋、重大缺口、替代方案與決定性資料取得方式。可以比較「值得研究什麼」，資訊不齊時不產生投資優劣排名。先交 company-research 補決策證據；初篩提案也須帶 Schema 2.0 的 investment_decision，但不得用篩選分數直接建議 Invest Now／Phased Entry／Wait for Conditions。

針對 0050／00646／00713 等不同目標 ETF，先確認各自曝險與指數方法，再比較同目標替代；不同市場／因子不能僅靠 TER 或歷史漲幅混排。假設資金與期間不等於風險承受能力或已同意配置比例。
